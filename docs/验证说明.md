- Android JVM 单元测试：97 项，失败 0，错误 0（原有 89 项及新增 8 项）。
- Android `assembleRelease` 构建成功。

- 桥接端 Release 构建零错误、零警告，独立发布程序 `--selftest` 通过。
- 保留原有协议、反推、双轮刹车、辅助控制、断线释放和自动驾驶断开回归。
- 两款机模的内存自检覆盖：机模身份、双轴不同校准、CL/FLX 卡位、零校准与非法校准拒绝、双杆不取平均、N1 变化不改变杆位、反推断线回慢车、过期/非法反馈、切机后旧数据清除、恢复反馈不重放旧接管、协议五往返及拒收旧协议。

- 本轮已安装手机端 1.5.1 并更新桌面桥接快捷方式；没有启动模拟器或修改飞机配置。游戏内验收仍待用户现场完成。

## 本机机模依据

- iniBuilds A320neo V2：本地包 `microsoft-aircraft-a320neo`，版本 1.0.21。其模型 XML 使用 `INI_AUTOTHRUST_TLA:1/2` 与独立动画变量，发动机动画使用 `INI_ENG1_N1`、`INI_ENG2_N1`；EFB 包含每根轴的各档 LOW/HIGH 与反推配置。
- FlyByWire：本地包显示 `A32NX (Stable)`，版本 `2020.15.0-41e8f8a4660ea3195dfff3780ed64795e9ebd640`；使用 `A32NX_AUTOTHRUST_TLA:1/2`、`A32NX_ENGINE_N1:1/2` 及各轴校准变量。
- 接口参考：[FlyByWire 系统接口](https://docs.flybywiresim.com/aircraft/a32nx/a32nx-api/a32nx-systems-api/)、[飞行甲板接口](https://docs.flybywiresim.com/aircraft/a32nx/a32nx-api/a32nx-flightdeck-api/)、[MSFS2020 SimConnect 局部变量](https://docs.flightsimulator.com/html/Programming_Tools/SimConnect/API_Reference/Events_And_Data/SimConnect_AddToDataDefinition.htm)。

读取这些定义只能支持接口选择，不能代替实际游戏运行中的数值与事件验证。

## 游戏内验收步骤

1. 分别在两款机模、默认涂装、地面状态测试，手机选中相同机模，确认双杆和 N1 有效。不同机模不得交叉套用。
2. 在座舱分别移动两根杆，核对手机①②各自位置，不应相互覆盖或取平均。再对齐双杆，测试手机接管。
3. 依次检查慢车、CL、FLX、TOGA；稳定卡位应完全对应。连续杆角对照记录误差，不预先宣称测量精度。
4. 开启自动推力并保持杆位 CL，改变目标速度；手机杆位应保持 CL，两个 N1 跟随对应座舱读数。稳定读数应与座舱显示精度一致。
5. 在 EFB 启用并校准双轴反推，检查全反推、反推慢车、松手回慢车，以及拔线释放。未配置轴反推时应明确显示不可用。
6. 检查切换手机机模、切换飞机、暂停/恢复、断线重连；旧数据不能冒充当前反馈，过期后不能自动恢复接管。
7. 通过同时拍摄座舱与手机记录动态延迟。约 10Hz 回传存在采样延迟；界面样本年龄不包含不可直接测量的网络在途时间。

以上游戏内步骤尚未执行。不能声称零延迟、逐帧一致或已完成实飞修复验收。可用新增只读诊断命令收集反馈，在不发送控制事件的情况下排查接口与校准。
