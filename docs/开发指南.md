# 开发指南

## 技术结构

- Android：Kotlin、AndroidX、最低 Android 13，目标 SDK 35。
- Windows 桥接：C#、.NET 8、Windows x64。
- 模拟器接口：随 MSFS2020 安装的原生 `SimConnect.dll`。
- 有线协议：协议四，状态包 26 字节，遥测包 47 字节，CRC-16/CCITT-FALSE。

手机端以约 100 Hz 提交不可变控制快照。桥接程序并行监听 USB 网络共享 UDP 和 `adb reverse` TCP，选择最近收到数据的通道，并以约 10 Hz 回传遥测。

## 构建环境

- JDK 17。
- Android SDK，包含 compile SDK 35。
- .NET 8 SDK。
- Windows x64 用于构建和运行桥接程序。

首次构建需要联网下载 Gradle 和 Android 依赖。仓库中的镜像配置用于网络受限环境，必要时可在 `settings.gradle.kts` 与 `gradle/wrapper/gradle-wrapper.properties` 中换回官方源。

## Android 构建与测试

Windows PowerShell：

```powershell
.\gradlew.bat testDebugUnitTest
.\gradlew.bat assembleRelease
.\gradlew.bat lintDebug
```

发布 APK 位于：

```text
app/build/outputs/apk/release/app-release.apk
```

当前 `release` 构建暂用 debug signing，便于侧载测试。公开分发或应用商店发布前，应创建并安全保管正式 keystore，再调整签名配置。仓库已忽略常见密钥文件。

## Windows 桥接构建

运行框架依赖版本：

```powershell
dotnet build bridge/AirYoke.Bridge.csproj -c Release
dotnet run --project bridge/AirYoke.Bridge.csproj -c Release -- --selftest
```

构建 Windows x64 自包含单文件版本：

```powershell
dotnet publish bridge/AirYoke.Bridge.csproj `
  -c Release `
  -r win-x64 `
  --self-contained true `
  -p:PublishSingleFile=true `
  -o dist/AirYoke-v1.4
```

## 诊断参数

| 参数 | 作用 | 是否操纵飞机 |
| --- | --- | --- |
| `--selftest` | 内存协议与控制事件自检 | 否 |
| `--dry-run` | 接收并显示手机输入 | 否 |
| `--simtest` | 检查 SimConnect 连接 | 否 |
| `--watch` | 观察模拟器状态 | 否 |
| `--mftest` | 检查 MobiFlight WASM/LVar | 否 |
| `--reversetest` | 实测反推事件 | 是 |
| `--controltest` | 实测油门、襟翼和减速板 | 是 |
| `--axistest` | 实测操纵轴方向 | 是 |

后三项只能在地面和安全状态下运行。

## 关键设计约束

- 未校准时，桥接端把副翼、升降舵和方向舵保持中立。
- 连续控制包在手机主线程每 20 毫秒提交，避免依赖传感器回调节奏。
- 油门只有在手动接管或短暂发送 CL 目标时才写入，避免与自动油门持续争抢。
- 离散辅助命令仅在 800 毫秒窗口内重复发送，窗口结束后让飞机系统重新接管。
- 500 毫秒输入超时会释放瞬时控制。
- 遥测只有在全部订阅字段均已收到且 1500 毫秒内新鲜时才标记有效。

## 提交问题

问题报告建议包含：

- 手机型号和 Android 版本。
- MSFS 版本、商店来源和完整机型名称。
- AirYoke 手机端与桥接端版本。
- 使用 USB 网络共享还是 ADB。
- 桥接程序输出及准确复现步骤。

请删除日志中的本机路径、用户名、网络地址和其他隐私信息后再公开提交。
